# .ini fixtures of the OpenMS test data which must not be replaced by the file
# `test-data.sh` writes with `<tool> -ini <old> -write_ini <new>`.
#
# -write_ini writes the *defaults* of the tool: -ini only selects the parameter
# set which gets augmented, so a value the tool fills in itself does not survive
# the round trip.  aux/check_ini_conversion.py reports every value that changed
# under its NODE/.../ITEM path (numbers are compared numerically); a file listed
# here keeps its original when that report is not empty.
#
# An unlisted file is still converted (the structural upgrade is the point - the
# test data ships ini files whose nodes have moved, and OpenMS fixes them on the
# fly at runtime), but the report is printed as a warning, so a value that
# silently becomes a default does not go unnoticed.
#
# IsobaricAnalyzer:type is a valid choice which the tool overrides with its
# default: TMTTenPlexMethod_test.ini says `tmt10plex` and came back as
# `itraq4plex`, so the generated test pinned that value and wrote an iTRAQ
# consensusXML (2611 b) where the upstream reference is a TMT one (12327 b) -
# which the wrapper's sim_size comparison rejects.  Upstream does not notice:
# TOPP_IsobaricAnalyzer_2 compares with -whitelist "id=" "<map" "?xml-stylesheet".
TMTTenPlexMethod_test.ini
TMTElevenPlexMethod_test.ini
# The two PeakPickerHiRes fixtures contain a deliberately invalid value; their
# whole purpose is the error handling, and the conversion "repairs" them.
PPHiRes_invalidValue.ini
PPHiRes_invalidValueSection.ini
